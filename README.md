## 1. Назва роботи
Meeting Room Reservation — Hexagonal Architecture

## 2. Опис use case
Система реалізує резервування переговорної кімнати на певний часовий слот. Основний функціонал полягає в перевірці перетинів у часі: система блокує спробу створення нового бронювання, якщо обраний час (TimeSlot) накладається на вже існуючі бронювання для обраної кімнати.

## 3. Обрана архітектура
У проєкті використано **Hexagonal Architecture** (також відому як Ports and Adapters).

## 4. Обґрунтування вибору
Цей підхід було обрано, оскільки він дозволяє ідеально ізолювати головне бізнес-правило (валідацію перетину часу) від інфраструктурного коду (фреймворку Spring Boot та бази даних). Завдяки цій архітектурі ядро системи повністю незалежне, легко тестується, а технічні деталі зберігання даних чи взаємодії з UI можна замінити без жодних змін у бізнес-логіці.

## 5. Структура проєкту
Проєкт логічно розділено на два основні пакети:
* `com.example.roomreservation.core` — ядро системи (не має залежностей від Spring).
* `com.example.roomreservation.infrastructure` — інфраструктура (робота зі Spring Boot).

## 6. Розподіл відповідальностей
У коді чітко видно межі відповідальності згідно з гексагональною архітектурою:
* **domain logic:** знаходиться у пакеті `core.domain` (сутність `Reservation`). Саме тут реалізовано метод `overlapsWith`, який відповідає за бізнес-правило перевірки перетину часу.
* **use case:** знаходиться у пакеті `core.usecase` (клас `RoomReservationService`). Він дістає дані, застосовує бізнес-правила домену та зберігає результат.
* **ports / interfaces:** знаходяться у `core.ports.in` (інтерфейс `ReserveRoomUseCase`) та `core.ports.out` (інтерфейс `ReservationRepositoryPort`). Вони є контрактами взаємодії ядра із зовнішнім світом.
* **adapters:** знаходяться у `infrastructure.adapters`. Вхідний адаптер `RoomReservationController` (у пакеті `in.web`) приймає HTTP-запити. Вихідний адаптер `InMemoryReservationRepository` (у пакеті `out.memory`) реалізує збереження даних.
* **технічна реалізація:** зосереджена у пакеті `infrastructure`. Там працює фреймворк Spring Boot, налаштовано Dependency Injection (`config.DomainConfig`) та розміщено In-Memory імплементацію бази даних.

## 7. Інструкція запуску
1. Відкрийте проєкт у середовищі розробки (наприклад, IntelliJ IDEA).
2. Запустіть головний клас `RoomReservationApplication` або виконайте в терміналі команду Maven: `mvn spring-boot:run`.
3. Додаток запуститься на порту `8080`.
4. Для перевірки роботи надішліть POST-запит (наприклад, через PowerShell):
